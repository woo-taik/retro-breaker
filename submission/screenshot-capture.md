# 심의·콘솔용 화면 캡처 지침

화면은 편집·합성·테두리·문구 추가 없이 **최종 빌드를 실제로 실행한 원본**으로 제출합니다. 현재 로컬 브라우저 캡처는 디자인 확인용이며, 심의·앱인토스 제출용 최종본은 앱인토스 샌드박스 또는 실제 토스 앱에서 다시 캡처합니다.

## 반드시 확보할 4장

| 파일명 | 환경 | 장면 | 확인할 내용 |
| --- | --- | --- | --- |
| `01-home.png` | 앱인토스 샌드박스 | 시작 화면 | 게임명, 시작 버튼, 규칙 안내 |
| `02-gameplay.png` | 앱인토스 샌드박스 | 공·패들·색상 벽돌이 보이는 진행 화면 | 60초, 생명, 점수, 패턴 표시 |
| `03-result.png` | 앱인토스 샌드박스 | 게임 종료 결과 | 점수, 최대 콤보, 다시 하기 |
| `04-continue-offer.png` | 앱인토스 샌드박스 | 리워드 광고 이어하기 제안 화면(광고 설정 시) | 선택형 광고, 생명 1개 보상, 한 판 한 번 안내 |

등급분류 신청에 필요한 수량과 파일 형식은 해당 신청 화면의 현재 안내를 우선합니다. 앱인토스에 직접 심의 증명서를 제출하는 경로는 등급분류증명서 PDF가 핵심이므로, 위 화면은 게임 내용 확인과 콘솔 등록 준비용으로 보관합니다.

## 캡처 절차

1. `npm run build`로 최종 `retro-breaker.ait`를 생성합니다.
2. 앱인토스 콘솔의 샌드박스 테스트 절차로 이 번들을 실행합니다.
3. 기기 상태바·알림·개인정보가 노출되지 않도록 정리합니다.
4. 위 장면마다 기기 기본 스크린샷 기능으로 캡처합니다.
5. PNG 원본을 `submission/captures/`에 원본 파일명 그대로 보관합니다. 이 폴더는 `.gitignore`에 추가하지 않았으므로, 민감한 화면이 있다면 외부 저장소에 별도 보관합니다.
6. 제출 직전 실제 실행 화면과 캡처 속 게임명·규칙·광고 보상 구조가 동일한지 비교합니다.

## 캡처에서 피할 것

- 스크린샷에 텍스트, 스티커, 프레임, 모자이크를 덧붙이는 편집
- 로컬 브라우저만으로 최종 앱인토스 실행 화면을 대체하는 것
- 실제 광고 소재 또는 광고 네트워크 화면을 심의용 주요 게임 화면으로 제출하는 것
- 테스트 광고 ID와 운영 광고 ID가 섞인 상태에서 최종 캡처하는 것
